# 00 · 项目概述与总体架构

> 本文档是 `IMPLEMENTATION_PLAN.md` 的补充：聚焦「**总体设计 / 目录映射 / 编码约定 / 分支工作流**」。
> 各 Phase 的**逐步骤工作清单**见 `01~06` 对应文档，**核心公式与接口契约**以 `IMPLEMENTATION_PLAN.md` 为权威。

## 1. 项目定位

边缘端（Jetson Orin NX）RGB-D 3DGS-SLAM，输入 D435i，输出实时位姿 + 高斯场，预留开放词汇 3D 语义场演进接口。目标产物（简历可写）：

1. 一个能在 **Jetson（aarch64 + 16GB 统一内存）** 上实时跑（15–30 FPS）的 RGB-D 3DGS-SLAM。
2. 一套 **显存/算力优化** 的可量化消融（FP16、视锥剔除、高斯剪枝、关键帧管理）。
3. 一个 **ROS2 Humble 具身接口**（订阅 RGB-D/IMU，发布 `/tf` 与高斯点云）。
4. 一条 **语言嵌入** 演进路径（MobileSAM + MobileCLIP → 语言高斯场 → 文本查询）。

## 3. 编码约定

1. **Python 3.10**，类型注解尽量齐全；`numpy<2`（cv_bridge/OpenCV ABI）。
2. 所有 CUDA 张量统一 `device="cuda"`；Jetson 上 `torch.cuda` 即统一内存，但**仍显式 `empty_cache()` 管理**。
3. 位姿约定：**世界→相机 `T_wc`（4×4）**，`P_cam = T_wc · P_world`；位姿扰动用左乘 `Exp(δ)·T`。**全项目一致**，代码里写清楚注释。
4. 深度单位**米**（float32）；ROS2 原始深度是 16UC1 mm，转换在 camera 层完成。
5. 每个 Phase 的产物先放 `experiments/` 验证，再抽象进 `src/`；跨 Phase 接口对齐 `IMPLEMENTATION_PLAN.md` 附录 A。

## 4. 分支工作流

```bash
git init
git checkout -b main
git checkout -b phase/1-edge-infra
# ... 完成 Phase 1 验收后合并
git checkout -b phase/2-rgbd-slam
# ... 依次推进 phase/3 .. phase/6
```

每个分支只做对应 Phase；**验收标准未通过不合并**。

## 5. 模块依赖速览

```
camera (P1) ──► slam (P2) ──► 优化 (P3) ──► ROS2 (P4)
    │                                            ▲
    └──► feature_factory (P5) ──► language_field + query (P6) ─┘
```

- `feature_factory` 与 `slam` 互不依赖，可并行开发。
- `language_field` 依赖 `slam`（几何场）与 `feature_factory`（监督特征）。
- `query` 依赖 `language_field`；ROS2 节点（P4）在 P6 增加查询服务。
