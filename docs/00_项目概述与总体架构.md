# 00 · 项目概述与总体架构

> 本文档是 `IMPLEMENTATION_PLAN.md` 的补充：聚焦「**总体设计 / 目录映射 / 编码约定 / 分支工作流**」。
> 各 Phase 的**逐步骤工作清单**见 `01~06` 对应文档，**核心公式与接口契约**以 `IMPLEMENTATION_PLAN.md` 为权威。

## 1. 项目定位

边缘端（Jetson Orin NX）RGB-D 3DGS-SLAM，输入 D435i，输出实时位姿 + 高斯场，预留开放词汇 3D 语义场演进接口。目标产物（简历可写）：

1. 一个能在 **Jetson（aarch64 + 16GB 统一内存）** 上实时跑（15–30 FPS）的 RGB-D 3DGS-SLAM。
2. 一套 **显存/算力优化** 的可量化消融（FP16、视锥剔除、高斯剪枝、关键帧管理）。
3. 一个 **ROS2 Humble 具身接口**（订阅 RGB-D/IMU，发布 `/tf` 与高斯点云）。
4. 一条 **语言嵌入** 演进路径（MobileSAM + MobileCLIP → 语言高斯场 → 文本查询）。

> **运行方式：宿主机本地直接运行（无 Docker 容器）**。依赖系统级 PyTorch-for-Jetson（PyPI aarch64 wheel）+ ROS2 Humble（apt）+ pyrealsense2（pip）。`docker/` 保留为可选备用方案，不作为主路径。

## 3. 编码约定

1. **Python 3.10**，类型注解尽量齐全；`numpy<2`（cv_bridge/OpenCV ABI）。
2. 所有 CUDA 张量统一 `device="cuda"`；Jetson 上 `torch.cuda` 即统一内存，但**仍显式 `empty_cache()` 管理**。
3. 位姿约定：**世界→相机 `T_wc`（4×4）**，`P_cam = T_wc · P_world`；位姿扰动用左乘 `Exp(δ)·T`。**全项目一致**，代码里写清楚注释。
4. 深度单位**米**（float32）；ROS2 原始深度是 16UC1 mm，转换在 camera 层完成。
5. 每个 Phase 的产物先放 `experiments/` 验证，再抽象进 `src/`；跨 Phase 接口对齐 `IMPLEMENTATION_PLAN.md` 附录 A。

## 4. 就绪检查惯例（所有下载 / 编译 / 安装前必做）

本项目**宿主机本地运行（无 Docker）**。任何「下载 / 编译 / 安装」步骤一律按以下顺序执行：

1. **先检查**目标是否已就绪：产物存在？依赖已装？源码已 clone？已编译过？版本匹配？
2. **已就绪 → 跳过**，不重复下载、不重复编译（宿主机已有大量已就绪项）。
3. **未就绪 → 才执行**准备动作（clone / pip install / cmake / colcon build）。
4. **执行后立即验证**（`import`、`--version`、`ros2 interface show` 等）。

最常用写法是 `||` 一行式：

```bash
python3 -c "import torch" || pip3 install torch==2.6.0 torchvision==0.21.0
ls third_party/SplaTAM >/dev/null 2>&1 || git clone https://github.com/spla-tam/SplaTAM.git third_party/SplaTAM
```

> **当前宿主机（2026-08-26）已就绪**：torch 2.11.0（CUDA 12.6）、torchvision 0.26.0、ROS2 Humble（apt）、numpy 1.26.4（<2）、colcon、cv2。
> 缺：pyrealsense2、3DGS 依赖、rasterizer、ws_src 构建 —— 按 `docs/01` §2 与各 Phase 补齐。

## 6. 模块依赖速览

```
camera (P1) ──► slam (P2) ──► 优化 (P3) ──► ROS2 (P4)
    │                                            ▲
    └──► feature_factory (P5) ──► language_field + query (P6) ─┘
```

- `feature_factory` 与 `slam` 互不依赖，可并行开发。
- `language_field` 依赖 `slam`（几何场）与 `feature_factory`（监督特征）。
- `query` 依赖 `language_field`；ROS2 节点（P4）在 P6 增加查询服务。

## 7. 数据集使用约定（各 Phase 验证统一口径）

数据分三级，按验证目的选用（依据 Phase 2 验证报告实证）：

| 层级 | 数据 | 位置 | 适合验证 | 不适合 |
|---|---|---|---|---|
| ① 合成 | 程序化 RGB-D 序列（Phase 2 生成器，真值可控、秒级生成） | `data/outputs/phase2/synth_scene.npz`（320x240）、`phase3/synth_scene_480.npz` | 机制/数值/单元验证：梯度、损失收敛、新组件；可复现 | 性能基准（分辨率/高斯数不真实）、语义验证（无语言语义） |
| ② Replica | 真实感渲染室内场景（纹理真实；深度/位姿程序生成，无真实传感器噪声） | `third_party/SplaTAM/data/Replica/`，加载器 `src/edge_3dgs_slam/dataset/replica.py` | 算法性能基线、文献对比（与 SplaTAM 论文同源）、性能优化基准（固定场景同输入对比）、室内语义验证 | 真实传感器噪声/光照/运动验证 |
| ③ D435i 自采 | Phase 1 数据流实采 | `data/raw/`（Phase 1 流程） | 部署/实时/鲁棒性最终验证 | — |

**验证矩阵（按目的选数据）**：

- 机制/数值/单元验证（梯度、损失、收敛、新组件）→ **① 合成**：快、可控、可复现
- 算法性能基线 + 文献对比 → **② Replica**：ATE 等指标可与 SplaTAM 论文直接对照
- 性能优化（显存/FPS，Phase 3）→ **② Replica 固定场景**：固定输入，优化前后同输入对比
- 语义/感知（Phase 5/6）→ **② Replica 场景级 + ③ D435i**：合成场景的球/盒/棋盘无语言语义，不用于语义验证
- 接口/回放（Phase 4）→ **② Replica 或 ① 合成回放**为话题流；真机走 ③
- 部署/实时/鲁棒性（最终）→ **③ D435i 自采**

**报告规范**：所有绝对数字（ATE/PSNR/FPS/显存）必须标注 **数据来源 + 分辨率 + 轨迹段/帧数**。
Phase 2 实测：同一指标在不同数据形态上可差 20 倍（合成环绕轨迹 ATE 24.9cm vs Replica 平缓段
0.86cm），未标注数据形态的数字不可比。相对结论（如 σ×2 最优、判据阈值）需在两种数据上
交叉确认后再写入文档。
